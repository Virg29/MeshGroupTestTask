# Parcel Service API

REST-сервис на Spring Boot 4 / Java 17.

## Стек

| Слой | Технология |
|---|---|
| Web | Spring Web MVC |
| ORM | Hibernate (через Spring Data JPA) |
| БД | PostgreSQL 16 |
| Миграции | Flyway |
| Кеш | Redis (Spring Cache) |
| Безопасность | Spring Security + JWT (JJWT) |
| Документация | SpringDoc OpenAPI (Swagger UI) |

## Что реализовано

### Аутентификация
- `POST /auth/login` — вход по email **или** по номеру телефона + пароль
- Возвращает JWT-токен; `user_id` хранится в `sub` токена
- Все защищённые эндпоинты принимают `Authorization: Bearer <token>`

### Пользователи
- `GET /user/me` — данные текущего пользователя (из JWT)
- `GET /user/search` — поиск с фильтрацией и пагинацией:
  - `name` — LIKE `{text}%`
  - `dateOfBirth` — записи где `date_of_birth > переданного` (формат `dd.MM.yyyy`)
  - `email`, `phone` — точное совпадение
  - `page`, `size` — пагинация
- `POST /user/email` / `DELETE /user/email/{id}` — добавить / удалить email
- `POST /user/phone` / `DELETE /user/phone/{id}` — добавить / удалить телефон

### Перевод средств
- `POST /user/transfer` — перевод баланса между пользователями
- Донор определяется из JWT; тело запроса: `{ "recipientUserId": 2, "amount": 100.00 }`

**Потокозащищённость переводов:**  
При одновременном переводе A→B и B→A возникает риск дедлока. Решение — оба аккаунта всегда блокируются в порядке возрастания `id` (`Math.min` первым). Это гарантирует единый порядок захвата блокировок для любых двух потоков и исключает взаимную блокировку.

**Пессимистичная блокировка строки:**  
Перед изменением баланса выполняется `SELECT ... FOR UPDATE` (`LockModeType.PESSIMISTIC_WRITE`) на обоих аккаунтах в рамках одной `@Transactional`. Строки в БД заблокированы до конца транзакции — параллельные запросы к тем же аккаунтам ждут снятия блокировки.

### Накопление баланса
- Шедулер запускается каждые **30 секунд**
- Начисляет +10% к балансу каждого пользователя
- Баланс не превышает `targetBalanceStockpiling` (207% от начального)
- Если 10% превышает потолок — баланс выставляется ровно в потолок
- Каждый аккаунт обрабатывается в **отдельной транзакции** с пессимистичной блокировкой

### Redis-кеш
- Результаты `GET /user/search` кешируются в Redis
- Ключ кеша включает все параметры фильтрации и пагинации
- Кеш инвалидируется автоматически при любом изменении данных:
  - добавление / удаление email или телефона
  - перевод средств (изменился баланс)
  - каждый тик шедулера накопления
- TTL кеша — 1 минута (страховочный backstop)

## Сборка и запуск

### Требования
- Docker + Docker Compose

### Запуск всего через Docker Compose
```bash
docker compose up --build
```
Поднимает PostgreSQL, Redis и приложение. Flyway автоматически накатывает миграции и заполняет тестовые данные.

### Локальная разработка (только инфраструктура в Docker)
```bash
docker compose up postgres redis
./mvnw spring-boot:run
```

### Swagger UI
```
http://localhost:8080/swagger
```
Для аутентификации: нажать **Authorize**, вставить токен из `/auth/login`.

## Тесты

Интеграционные тесты transfer-эндпоинта: `src/test/java/com/example/demo/TransferIntegrationTest.java`

Покрывают: успешный перевод, 401 без токена, 400 самому себе, 400 недостаточно средств, 400 невалидная сумма, 404 несуществующий получатель, **потокобезопасность** (20 встречных потоков — суммарный баланс не меняется).

Используют Testcontainers (PostgreSQL + Redis) + MockMvc.

```bash
./mvnw test -Dtest=TransferIntegrationTest
```
